# Structural correction and Skeleton Studio handoff — 2026-09-11

Al's manual alligator prompts exposed two failures after the first repair: rejected geometry was only sent back as a short error string, and the app action planner recast that failure as a request to select a body part. A trailing instruction to move the completed character to Skeleton Studio was also being sent into the geometry runner.

The creation planner now retains every rejected proposal, its measured part-level diagnostics and subsequent correction decisions in the local build record. Diagnostics cover duplicate or buried geometry, missing humanoid roles, inverted anatomy, laterality, grounded feet, disconnected joints, and forward snout/backward tail orientation. Explicit dimensions no longer bypass validation. Retries receive the rejected plan and these constraints, rather than just the last error sentence.

For failed humanoid plans with default dimensions, the existing procedural author can propose a bounded biped layout with separately positioned body parts and the requested snout/tail. Grudge receives this proposal alongside the rejected plan and original request. Only an accepted and independently validated correction proceeds to immutable asset creation. This is a procedural layout correction, not model training or a neural generation fallback. Explicit component dimensions and coordinates are not replaced by the default layout. Simple overall height scales the layout. Unknown additional named anatomy is retained and still checked.

The app action record now grounds creation failures in the observed error. New-model requests hide examples and part names belonging to the previous asset. A trailing “move character to Skeleton Studio once completed” is separated from the geometry instruction; ordinary spatial movement and negated handoffs are retained in the creation request. The continuation activates the saved model's handoff button and requires a successful load in Skeleton Studio before reporting completion. Pending model handoffs bypass the generic preview substitution and load the exact source file.

The prompt panel stays expanded in Skeleton Studio, including during the handoff, with a “Continue with this model” heading and a follow-up field. A geometry or surface follow-up first activates “Revise model with prompt”, which restores the exact loaded creation revision (or selects an independent working copy for an external source). The same controller runs its edit and returns the revised file to Skeleton Studio unless the user requests another destination. Bone, rig, pose and clip requests stay with the current studio controls.

The automated checks cover the reported inverted coordinates, named diagnostic feedback, repair validation, buried and detached parts, height scaling, explicit-measurement preservation, no-tail wording, handoff splitting and factual failure messages. Real-model packaged verification and final runtime identity are recorded below when complete.

This remains basic segmented procedural geometry with authored surface patterns and modest idle animation. Structural validation is separate from visual quality and rigging acceptance. No skin rig, neural finishing, deployment, commit or push is implied.
